# Contributing

Follow AGENTS.md and docs/project/definition-of-done.md. Issues are unassigned until a real contributor accepts them. Priorities are sequencing guidance, not dates. One focused issue and independently reviewable PR at a time. Dependencies must be verified, not merely removed from the description. Branch naming: dev-a/issue-<number>-<slug> or dev-b/issue-<number>-<slug> (see docs/project/governance.md); commit messages describe the outcome.

Planning changes need requirement, ADR, dependency and test impact review. Product PRs include synthetic test evidence, screenshots where useful, migration/backout notes, data exposure review and the standard implementation report. Do not bypass checks. A maintainer must deliberately configure protection once CI exists; this baseline does not claim protection is enabled.

No team email, institutional owner or code licence is invented. Discuss source licensing and appoint real maintainers before public redistribution.

Branch/PR rules, ownership vacancies and the planning-only boundary are in [docs/project/governance.md](docs/project/governance.md).
