# Accessibility and localization

Planning baseline: 2026-11-07. Proposed design; no participant collection or product implementation has occurred.

Target WCAG 2.2 AA with manual review. Keyboard users can search/filter/select via equivalent list; map canvas is never the only path. Escape closes overlays, focus is trapped only in true modals and restored; skip links and landmarks; status announcements use polite live region without GPS spam. Controls have 44px preferred targets, 24px WCAG minimum exceptions assessed explicitly; contrast 4.5 text/3 UI and visible focus. 200% zoom and 320px reflow without lost form controls. Tables/captions accompany charts; transcripts/captions accompany audio/video. Slider has arrow keys and non-drag alternative. Reduced motion removes fly-to/automatic panorama rotation. Screen reader tests on NVDA/Chrome and VoiceOver/Safari are manual release gates.

Localization baseline: externalized keys/plural/date/number formatting, `lang` attributes, English and reviewed Gujarati core navigation/consent/form content. Hindi expansion is M12; do not advertise untranslated screens. Keep raw respondent language, transcription and translation separately with reviewer/provenance. Missing translations show labeled English fallback; no machine-only legal/consent translation. Names have multilingual aliases; search does not transliterate source evidence destructively.

## Automated accessibility audit in a real browser (#114, automated part)

`apps/web/e2e/accessibility.spec.ts` (33 tests, headless Chromium, run in CI against the production build). **This is the automated part only. #114 stays open: a person using a screen reader, switch devices and real phones, and a fluent reviewer for Gujarati and Hindi, have not reviewed the site (human action H-A11Y).**

**axe-core with WCAG 2.0/2.1/2.2 A and AA rules plus best practice**, including **colour contrast** (which the jsdom component tests cannot check), run on 13 routes (home, explorer with a selected place and a filter, place profile, Then & Now page, panorama page, Voices, Insights, methodology, sources, accessibility, stories placeholder, and not-found) at 1280x800 and 375x667. Result at merge: no violations on any of the 26 scans. Synthetic data, stubbed map tiles and images.

**Structure and keyboard.** Every route has exactly one `h1`, one `main`, `lang="en"` and a distinct page title. The test found one real defect, fixed in this change: the Then & Now and panorama pages kept the generic site title, so two different pages shared one title (WCAG 2.4.2); they now name the place. The skip link is the first tab stop, is visible when focused and moves focus to the main region. Tabbing through the explorer reaches the search box, filters, map controls, attribution link, place buttons and footer links without a trap and without landing on zero-size elements. At 200% text size and 640px width, four representative pages do not scroll sideways. With reduced motion requested no animation runs on the home page. With forced colours active the focused search box keeps a visible outline. The language selector offers only English; Gujarati and Hindi are disabled until a fluent speaker has reviewed them.

**What is not covered.** Screen readers (NVDA, VoiceOver, TalkBack): not run. The map canvas is not keyboard-navigable by design; the list and details are the accessible alternative. Firefox and Safari: not run. Real touch devices and the soft keyboard: not run (#82, #117). Cognitive and plain-language review of the wording: not done. Gujarati and Hindi text does not exist yet, so right-to-left or script-specific issues cannot be tested. axe cannot judge alt-text quality or whether instructions make sense; a human must.
