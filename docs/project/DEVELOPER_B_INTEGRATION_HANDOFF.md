# Developer B to Developer A integration handoff

Written 2026-11-08 for Varun (`varunkarthic`). Nothing here changes issue ownership. Each row says what the public-experience side already has, what is missing on the platform side, and how to check it. Everything on the Developer B side runs against the synthetic mock (`pnpm dev:mock`, `/api/v1/public`) and the shared contract v1.0.0 in `packages/contracts`; **no live integration has been verified**.

How to check any integration: point the web app at the real API (`VITE_API_BASE`), run `python scripts/check_public_contracts.py --base-url <api>`, then `E2E_TARGET=preview pnpm --filter @makarba/web test:e2e` with the API stubs removed for the relevant journey, and the abuse-case register tests (`apps/api/src/threat-model.test.ts`) against the live router.

## Server hardening items found by the threat-model review (issue #41)
Mount `notFound` then `safeErrors` from `apps/api/src/safe-errors.ts` after all routes (Express otherwise prints stack traces and file paths outside production). Add rate limiting and login throttling (none exists). Make unauthenticated attempts on private routes auditable. Mount every private router behind `createApp` so `Cache-Control: no-store` applies. Details and tests: `docs/architecture/threat-model.json`.

## Not for suppression
The baseline in `docs/project/audit-baseline.json` makes advisories visible; it does not make them acceptable. The zod advisory affects a **runtime** package. The fix and a regression check are required before any production-readiness claim, and entries expire on 2026-12-31 (CI fails after that date).
