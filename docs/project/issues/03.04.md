### Summary

### Why this is needed
Enforce capability matrix across API and UI enables the authentication, privacy and data security workstream while preserving the researcher-led evidence chain. Without this deliverable: hidden button alone never substitutes server authorization is not established or verified.

### User story
As a authorised team member, I need this reviewed capability so that uI actions and API handlers agree with approved capabilities.

### Scope
- UI actions and API handlers agree with approved capabilities.
- Implement/review the associated contract and observable error states described in `docs/architecture/privacy-security.md`.
- Capture evidence for the negative case: Hidden button alone never substitutes server authorization.

### Out of scope
Other backlog issue deliverables, unrelated refactors, real data committed to Git, and unapproved paid-provider activation. Planning/design/research issues produce reviewed artifacts rather than application code; implementation issues build only the stated capability.

Add route guards, ownership checks and explicit admin separation. Follow `docs/architecture/privacy-security.md`, `docs/architecture/data-model.md` and the relevant ADR.
