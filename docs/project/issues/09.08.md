### Summary
Independent reviewer approves exact public payload from current eligible revisions.

### Why this is needed
Implement publication preview approval and revoke enables the research administration and publication management workstream while preserving the researcher-led evidence chain. Without this deliverable: stale consent, self approval or withdrawal invalidates affected public copies is not established or verified.

### User story
As a research lead, I need this reviewed capability so that independent reviewer approves exact public payload from current eligible revisions.

### Scope
- Independent reviewer approves exact public payload from current eligible revisions.
- Implement/review the associated contract and observable error states described in `docs/design/admin-dashboard.md`.
- Capture evidence for the negative case: Stale consent, self approval or withdrawal invalidates affected public copies.

### Out of scope
Other backlog issue deliverables, unrelated refactors, real data committed to Git, and unapproved paid-provider activation. Planning/design/research issues produce reviewed artifacts rather than application code; implementation issues build only the stated capability.

### Technical approach
Versioned snapshots, allowlisted lineage and atomic publish/invalidate jobs. Follow `docs/design/admin-dashboard.md`, `docs/architecture/data-model.md` and the relevant ADR. Keep migrations, runtime validation and UI contracts consistent where this task changes them. Document a justified alternative before changing architecture.

### Data and privacy considerations
Review access is study-scoped. Approval/revocation/export actions are audited and consent-compatible. Do not copy sensitive inputs into issue comments, test artifacts or operational logs.
