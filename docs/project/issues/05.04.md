### Summary
Repeated/concurrent same-operation requests return one durable receipt/write.

### Why this is needed
Implement idempotent transactional sync enables the offline fieldwork, synchronisation and media workstream while preserving the researcher-led evidence chain. Without this deliverable: same key changed payload gets 409; response loss retry adds no duplicate is not established or verified.

### User story
As a field researcher, I need this reviewed capability so that repeated/concurrent same-operation requests return one durable receipt/write.

### Scope
