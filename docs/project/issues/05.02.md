### Summary
Draft saves acknowledge only successful vault transactions and survive restart within tested limits.

### Why this is needed
Persist protected recoverable local drafts enables the offline fieldwork, synchronisation and media workstream while preserving the researcher-led evidence chain. Without this deliverable: quota failure/key loss/eviction produce honest recovery limits is not established or verified.

### User story
As a field researcher, I need this reviewed capability so that draft saves acknowledge only successful vault transactions and survive restart within tested limits.

### Scope
- Draft saves acknowledge only successful vault transactions and survive restart within tested limits.
- Implement/review the associated contract and observable error states described in `docs/architecture/offline-sync.md`.
- Capture evidence for the negative case: Quota failure/key loss/eviction produce honest recovery limits.

### Out of scope
Other backlog issue deliverables, unrelated refactors, real data committed to Git, and unapproved paid-provider activation. Planning/design/research issues produce reviewed artifacts rather than application code; implementation issues build only the stated capability.

### Technical approach
IndexedDB protected vault, autosave marker, quota alarms and key-unlock design. Follow `docs/architecture/offline-sync.md`, `docs/architecture/data-model.md` and the relevant ADR. Keep migrations, runtime validation and UI contracts consistent where this task changes them. Document a justified alternative before changing architecture.

### Data and privacy considerations
Local drafts are sensitive; protection, storage loss and offline revocation limitations must be explicit. Do not copy sensitive inputs into issue comments, test artifacts or operational logs.
