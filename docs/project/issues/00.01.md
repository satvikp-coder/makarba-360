### Summary
Branch/PR rules, ownership vacancies and planning-only boundary are documented.

### Why this is needed
Establish repository governance enables the requirements, research and repository foundation workstream while preserving the researcher-led evidence chain. Without this deliverable: no real team or source licence invented is not established or verified.

### User story
As a project contributor, I need this reviewed capability so that branch/PR rules, ownership vacancies and planning-only boundary are documented.

### Scope
- Branch/PR rules, ownership vacancies and planning-only boundary are documented.
- Implement/review the associated contract and observable error states described in `docs/product/requirements.md`.
- Capture evidence for the negative case: No real team or source licence invented.

### Out of scope
Other backlog issue deliverables, unrelated refactors, real data committed to Git, and unapproved paid-provider activation. Planning/design/research issues produce reviewed artifacts rather than application code; implementation issues build only the stated capability.

### Technical approach
Review AGENTS, contribution/security policy and licence decision register. Follow `docs/product/requirements.md`, `docs/architecture/data-model.md` and the relevant ADR. Keep migrations, runtime validation and UI contracts consistent where this task changes them. Document a justified alternative before changing architecture.

### Data and privacy considerations

### Dependencies
No issue blockers; verify repository access and planning baseline. Blockers require verified completion evidence before implementation. External institutional/provider gates in the linked documents remain effective even when issue blockers close.
